# Handoff: AMOffline (AMS, Appointment Management System)

Last updated: 16 October 2026.

The app is called **AMOffline** (renamed from AMS on 16 October 2026). That name is used everywhere
people see it: the window, the website, the downloads, the installers, the data folder (`~/AMOffline`)
and the Linux command (`amoffline`). The code keeps its coursework names: the `AMS/` project folder,
package `ams`, classes `AMS` and `AMSWindow`, and the `-Dams.*` and `AMS_*` test settings.

PDSA coursework project. The core is a priority-ordered **doubly linked list** of appointments
(`AMS/src/ams/LinkedList.java`) with bubble-sort methods for priority, name, date created and
scheduled date/time. On top of that there is now:

- the original **console app** (`ams.AMS`)
- a **desktop window app** (`ams.AMSWindow`, Swing), with light and dark themes
- a **download website** (`website/`)
- **one-step installers** for Windows and Linux

The window app uses the same `LinkedList`. Sorting, inserting, updating and deleting all go
through its methods, so the data-structure work is still the heart of the app.

## Set up on another machine

1. **Get the code:**
   ```
   git clone https://github.com/B1N4L/pdsa-cw.git
   cd pdsa-cw
   ```
2. **Install JDK 21** (Eclipse Temurin):
   - Windows: `winget install EclipseAdoptium.Temurin.21.JDK`
   - Ubuntu/Debian: `sudo apt install openjdk-21-jdk`
   - macOS: `brew install --cask temurin@21`
3. **Run it.** From the `AMS` folder, so it uses `src/ams/appointment-list.txt`:
   ```
   javac -d out/classes src/ams/*.java
   java -cp out/classes ams.AMSWindow      # window app
   java -cp out/classes ams.AMS            # console app
   ```
   In IntelliJ/NetBeans, set the working directory to `AMS/` and the main class to `ams.AMSWindow` or `ams.AMS`.
4. **Run the checks** (uses a throwaway data folder):
   ```
   java -cp out/classes -Dams.data=/tmp/ams-test packaging/tools/SmokeTest.java
   ```
5. **Build the downloads** (Git Bash on Windows, or any bash). On Windows, set `JAVA_HOME` first if `javac` isn't on the PATH:
   ```
   SITE_URL=https://amoffline.netlify.app bash AMS/packaging/build-release.sh
   ```
   - `SITE_URL` is written into the one-command installers. Without it, they point to `http://localhost:8137`.
   - `AMOffline-Windows.zip` is only made when building **on Windows**.
   - `AMOffline-Linux-x64.tar.gz` (Java included) needs the **Linux JDK of exactly the same version** as
     your JDK (check `jlink --version`). Its jmods are taken from
     `AMS/out/linux-jdk-download/jdk-linux.tar.gz`. For 21.0.12.1 that is
     `https://github.com/adoptium/temurin21-binaries/releases/download/jdk-21.0.12.1%2B1/OpenJDK21U-jdk_x64_linux_hotspot_21.0.12.1_1.tar.gz`
     (207 MB; check it against the `.sha256.txt` next to it). Without it, the build skips that file.
6. **Preview the website:** serve the `website/` folder with any static server on port 8137, e.g.
   `python -m http.server 8137 -d website` or `npx serve -l 8137 website`. Then open http://localhost:8137.
   The download buttons don't work in a local preview: the files are on GitHub releases, and the
   `_redirects` file that forwards to them only works on Netlify.

## How things work (decisions worth knowing)

- **Where data lives.** Run from the project, it uses `AMS/src/ams/appointment-list.txt`. Installed,
  it uses `~/AMOffline` (`C:\Users\<you>\AMOffline`), with backups in `~/AMOffline/Backups`. `-Dams.data=<folder>`
  overrides it, which tests use. The theme choice goes in `settings.properties` in the same folder.
- **File format.** Blocks of `Label: value` lines with a blank line between them. The reader matches
  fields by label, so old files without the newer `Scheduled:` line still load. Line breaks inside
  text are stored as `\n`.
- **Themes.** `UiKit` has a light and a dark value for every colour. Swing's cross-platform (Metal)
  look is used on every OS with a custom colour theme, plus custom dropdown and scrollbar styles,
  so menus, dialogs and file pickers match in both themes. The system theme is read from the Windows
  registry, macOS `defaults`, or GNOME `gsettings` / KDE `kdeglobals`, and re-checked every
  3 seconds. `-Dams.theme=light|dark` forces one, which screenshots use.
- **Windows install.** There is deliberately **no generated `.exe` launcher**. Windows 11's Smart App
  Control blocked jpackage's unsigned `AMS.exe` (it has no "Run anyway"). Instead the zip carries a
  `jlink` Java runtime, whose `java.exe`/`javaw.exe` are signed by the Eclipse Foundation. The installer
  makes Start menu and desktop shortcuts to `javaw.exe -jar app\AMOffline.jar` and adds an uninstall
  entry under HKCU, so no admin rights are needed. Smart App Control allows all of this.
  `install.ps1` reads `AMS_INSTALL_DIR`, `AMS_SHORTCUT_DIR`, `AMS_REG_KEY` and `AMS_NO_LAUNCH`
  so tests can install into temp folders.
- **Linux install.** It installs per user into `~/.local/share/amoffline`, `~/.local/bin/amoffline` and a `.desktop`
  entry. It uses the bundled runtime on x86_64, otherwise the system's Java 17+. The online script
  picks the right tarball for the processor.
- **Website.** Plain static HTML. The install commands fill in the page's own address. The page asks
  GitHub's API for the latest release to show its version and file sizes (falling back to
  `downloads/release.js`). Dark visitors see dark screenshots.
- **Where downloads live.** The four app files are attached to the **latest GitHub release** of
  B1N4L/pdsa-cw, not uploaded to Netlify. `website/_redirects` forwards `/downloads/<file>` to
  `github.com/B1N4L/pdsa-cw/releases/latest/download/<file>` (forced 302), so the buttons and the
  one-command installers keep using the site's own address and downloads don't use Netlify's
  free-plan credits. The repo must stay public, and file names must not change.
- **Releases are automatic.** Publishing a release on GitHub (tag like `v1.2.0`) runs
  `.github/workflows/release.yml` on a GitHub Windows machine: it installs Temurin 21, downloads the
  matching Linux JDK from Adoptium, runs SmokeTest, runs `build-release.sh` with `VERSION` taken from
  the tag, and uploads the four files to that release. It takes about 10 minutes; until it finishes,
  the latest release has no files and the download buttons show GitHub's 404. To build an existing
  release again, use Actions › Release › Run workflow with its tag.
- **The website deploys itself.** Netlify is connected to the repo and reads `netlify.toml`. It
  deploys from `main` only when `website/`, `AMS/packaging/` or `netlify.toml` changed
  (`netlify-skip-build.sh`), because every deploy uses free-plan credits (15 of 300 a month).
  Deploy previews and branch deploys are always skipped.

2. **Test on a real Linux desktop** (e.g. Ubuntu 24.04): the bundled runtime, the menu entry,
   dark-mode detection under GNOME/KDE, and `curl … | sh`. These were only checked from Windows.
3. Optional: **code-sign** for Windows (e.g. Azure Trusted Signing, or Certum's open-source certificate).
   That would make the "Run Install AMOffline?" prompt friendlier.
4. Known limits:
   - In dark mode, the Windows title bar stays light (Java can't change it).
   - Pinning the *running* window to the taskbar pins Java. Pin from the Start menu shortcut instead.
   - macOS only has `AMOffline.jar`, which needs Java.
